# 普通用户交互流程

## 目标

把“下载项目、理解命令、修改 JSON、运行测试”的开发者流程，压缩成“提供图片、查看检查结果、确认预览”的三步体验。实现细节仍需完整执行，但不应成为普通用户的操作负担。

## 标准流程

普通目录中没有主题引擎时，先说明将从官方仓库准备固定的 `v0.3.0-rc.2` 工作区；经正常命令审批后运行引导脚本。不得要求普通用户手动 clone，也不得跟随 `main` 或其他可变分支。

### 第一步：用户提供素材

推荐触发语：

```text
使用 $codex-skin-maker，把这张图片做成 Codex 皮肤。先检查和生成，不要直接应用。
```

接受以下输入：

- 一张图片：自动生成浅色和深色模式；
- 两张图片：用户指定哪张用于浅色、哪张用于深色；
- 图片加主题名：例如“西交红蓝”“水墨实验室”“极简白”；
- 用户仅描述风格但没有图片：先说明该 Skill 主要使用用户提供或明确授权的图片，不应自行抓取来源不明的素材。

### 第二步：自动生成与检查

向用户展示进度时只报告有意义的阶段：

1. 环境与 Codex 版本检查；
2. 图片与授权风险检查；
3. 浅色/深色主题生成；
4. 主题校验、自动化测试和离线 Dry Run；
5. 等待真实预览确认。

不要逐条输出内部文件读取、路径遍历或每一条测试日志。失败时再展示相关命令和精简错误。

### 第三步：用户确认预览

首次生成完成后的推荐回复：

```text
皮肤已经生成，但尚未应用。

主题：西交红蓝
深色模式：已生成并通过检查
浅色模式：已生成并通过检查
环境检查：通过
自动化测试：通过
离线 Dry Run：通过

真实预览会临时连接本机 Codex 进程，失败时会立即恢复。
回复“预览深色”或“预览浅色”即可继续。
```

只有用户明确批准后才执行真实 `preview`。

## 常用请求示例

### 单图双模式

```text
使用 $codex-skin-maker，把 campus.jpg 做成浅色和深色两套皮肤。主题叫“校园晚霞”，先不要应用。
```

### 双图分别适配

```text
使用 $codex-skin-maker，light.png 用于浅色，dark.png 用于深色。尽量保持左侧文字清晰，先完成测试。
```

### 只调整已有皮肤

```text
使用 $codex-skin-maker，把当前皮肤的侧栏再压暗一点，正文区域不要显示壁纸。只生成和验证。
```

### 恢复原版

```text
使用 $codex-skin-maker，退出当前皮肤并检查是否完全恢复。
```

恢复请求应直接运行安全的 `disable` 和状态检查，不需要重新生成主题。

## 不应让用户承担的操作

正常情况下不要要求普通用户手动：

- 编辑 JSON；
- 查找 Electron PID；
- 打开 Inspector；
- 修改 `WindowsApps` 或 `app.asar`；
- 复制长 PowerShell 命令；
- 判断测试日志；
- 清理残留状态文件。

只有自动流程失败且必须人工排查时，才给出最短、可复制的诊断步骤。

## 小红书发布路径

面向小红书用户的推荐说明：

1. 在 Codex 中安装 `codex-skin-maker` Skill；
2. 打开一个安全的本地工作区；
3. 把自己的图片拖给 Codex；
4. 输入“一句话换肤”提示词；
5. 查看检查摘要；
6. 明确确认后预览；
7. 随时说“恢复原版”。

传播文案可以强调“一张图、一句话、可恢复”，但必须同时注明 Windows、Microsoft Store 版 Codex、版本兼容性和非官方实验性限制。
